# Film X

[English](README.en.md) | [中文](README.md) | 日本語

ブラウザー内で動作する、フィルム画像の処理ツール集です。画像のデコード、編集、書き出しはすべて手元の端末で行われ、サーバーにアップロードされることはありません。

## ツール

### ハーフサイズフィルムの分割

- TIFF、JPEG、PNG、WebP をまとめて読み込めます。ファイルをページに直接ドラッグ＆ドロップすることもできます。
- スキャン画像ごとに分割位置と中央の隙間の幅を自動検出し、手動で微調整できます。
- 左右の画像を個別に回転でき、現在の設定をすべての画像に適用することもできます。
- JPEG、PNG、WebP、TIF で書き出せます。一括書き出しの結果は ZIP にまとめてダウンロードできます。
- JPEG と WebP の書き出しでは画質を調整できます。

### レイアウト合成

- 「フィルムサイズ」パネルで、ハーフサイズかフルサイズか、1 枚か 2 枚かを選べます。組み合わせは、1 枚のハーフサイズ、2 枚のハーフサイズ（初期設定）、1 枚のフルサイズ、2 枚のフルサイズの 4 通りです。画像スロットの数は選択したモードに連動し、TIFF、JPEG、PNG、WebP はクリックして選択するか、ドラッグ＆ドロップで読み込めます。スロット数より多くのファイルをドロップした場合は、先頭から順に使われます。
- サイズを切り替えると推奨の配置が適用されます。ハーフサイズは横並び、フルサイズは縦並びです。1 枚に切り替えると、2 枚目の画像は削除されず一時的に非表示になり、2 枚に戻すと復元されます。2 枚目のスロットだけに画像があった場合は、表示されているスロットに移動します。
- 2 枚のときは、横並びと縦並びのレイアウト（サイズ切り替え後も変更可能）と、画像の順序の入れ替えに対応しています。1 枚のときは、コマの配置の向き、コマの間隔、入れ替えの操作、画像の調整でのコマの選択は表示されません。
- キャンバスの縦横比は、プリセット、任意の比率、画像と間隔に基づく自動計算（初期設定）から選べます。
- キャンバスサイズは自動モードと手動モードに対応しています。手動モードに切り替えても、現在のサイズは維持されます。画像を読み込む前は、空のコマと自動サイズにサイズごとの初期値が使われます。ハーフサイズは 2:3 の縦長で長辺 1596 px、フルサイズは 3:2 の横長で長辺 2394 px です（36 mm と 24 mm の比で、ハーフサイズの長辺の 1.5 倍）。読み込み後は、画像の実際のサイズと比率が使われます。
- プリセットまたは任意の比率での自動キャンバスサイズは、次のとおりです。1 枚のときは画像が元のピクセルサイズ（拡大率 1）で表示され、「枠に合わせて切り抜き」では画像の一辺がコマにちょうど収まる小さいほうのキャンバス、「画像全体を表示」では大きいほうのキャンバスになります。2 枚のときは、短辺が画像の長辺と対応する外側の余白の合計になります。自動比率では、各コマの長辺が画像の長辺と等しくなり（横長の画像は幅、縦長の画像は高さに合わせます）、どちらの配置の向きでも画像が元のサイズで表示されます。自動サイズでも、最長辺の上限は 8000 px です。
- 手動モードではキャンバスの幅や高さを直接入力できます。最長辺の上限は 8000 px です。
- 手動モードでは画像を選択し、スライダーや数値入力で拡大・縮小したり、キャンバス上で直接ドラッグして位置を調整したりできます。
- 外側の余白と画像間の間隔は、スライダーでも直接入力でも調整できます。外側の余白は一括設定のほか、上・右・下・左を個別に設定できます。
- キャンバスを埋めるように切り抜く表示と、画像全体を収める表示を選べます。背景色は RGB の 16 進数で入力でき、背景パターンは単色、チェック柄、ドット柄から選べます。
- キャンバスの外側に、幅 24–240 px のフィルムのパーフォレーション（送り穴）付きの帯を追加できます。配置は上下または左右、色は背景に合わせるか黒を選べます。穴は角が丸く、135 フィルムに近い比率で密に並び、帯の内側寄りに配置されるため、外側にエッジ文字用の余白が残ります。帯の幅はキャンバスサイズに含まれません。
- 両側の帯の外縁に沿って、最大 48 文字のエッジ文字を互い違いの位置に繰り返し印字できます（左右配置では下から上へ読む向き）。文字色はアンバー、白、黒のプリセット、または任意の 16 進数カラーから選べます。
- 「フィルムの質感」（初期状態はオフ）を有効にすると、背景キャンバスとパーフォレーションの帯に、固定シードによる再現性のあるフィルムの粒子が加わります（写真そのものには適用されません）。穴の縁はやわらかく少し不規則になり、わずかな明暗の変化も加わります。PNG の穴は引き続き透明です。
- PNG ではパーフォレーションの穴が透明になり、作業プレビューでは市松模様で表示されます。JPEG では、背景に合わせた帯の穴は黒、黒い帯の穴は白になります。
- JPEG または PNG で書き出せます。

### フォトフレーム

- 1 枚の写真にフレームを付けられます。TIFF、JPEG、PNG、WebP は、クリックして選択するか、ドラッグ＆ドロップで読み込めます。正方形、6×4.5、6×7、3:2、ハーフサイズの縦長、XPan のワイドなど、あらゆる画面比率に対応し、フィルムのスキャン画像にもデジタル写真にも使えます。縁、文字、影の大きさは写真の幅と高さの幾何平均を基準に比例して計算されるため、比率の異なる写真でも統一感のある仕上がりになります。
- レイアウトはボーダー、ギャラリー、フロート、情報バーの 4 種類です。レイアウトを選ぶと、おすすめの縁、影、表示内容が適用され、そのあとも上・左右・下の縁の幅、フレームの色（白、アイボリー紙、ライトグレー、チャコール、黒のプリセットを含む）、文字色を個別に調整できます。
- 写真の影には、なし、接地、ソフト、浮き上がり、環境光、ディープ、斜め、ハードの 8 種類のプリセットがあり、強さは 0–150% で調整できます。背景を追加すると、フレームがプリントのように背景の上に置かれ、背景色、余白、フレームの影を個別に設定できます。
- 取り込み時に EXIF を端末内で読み取り（JPEG、PNG、WebP、TIFF のいずれもメタデータのある少量のバイトだけを読みます）、カメラ機種、レンズ、焦点距離、絞り、シャッタースピード、ISO、日付を自動入力し、メーカーに応じてブランドも自動で選びます。すべての項目は手動で編集でき、編集した項目は写真を切り替えても保持されます。「EXIF から入力」でいつでも上書きすることもできます。
- 写真の種類はデジタルとフィルムから選べます。フィルムスキャナー（Noritsu、Frontier、Coolscan、Flextight、Epson など）が書き込んだ EXIF を検出すると自動的にフィルムに切り替わり、スキャナーをカメラとして入力することはありません。フィルムでは露出の項目の代わりにフィルムの種類を入力し、カメラ・レンズ・フィルムは一度入力すればロール全体に引き継がれます。
- カメラ、フィルム、スマートフォンのブランドを 40 件内蔵しており、検索して選べるほか、「カスタム」で任意の文字も入力できます。ロゴには、内蔵の図形（ブランドによっては複数）、ワードマーク（クラシック斜体、ローマン、ジオメトリック、ボールド、ワイド、スクリプト、モノの 7 スタイル）、カスタム画像（背景が透明な PNG がおすすめ）、または表示なしを選べます。単色のロゴは元の色のまま使うか、文字色に合わせるか、任意の色を指定できます。キャッチコピー（例：CREATE TO INSPIRE）は表示のオン・オフと編集ができます。
- OFL ライセンスのオープンソースフォント 18 種（Playfair Display、Bodoni Moda、Cormorant Garamond、DM Serif Display、Cinzel、Italiana、Jost、Josefin Sans、Montserrat、Syncopate、Michroma、Orbitron、Bebas Neue、IBM Plex Mono、Courier Prime、Great Vibes、Dancing Script、Caveat）のラテン文字サブセットをアプリに同梱しており、オフラインでも使えます。日本語・中国語の文字にはシステムのゴシック体、明朝体、楷書体も選べます。ワードマークとキャプションで、フォント、太字、斜体、大文字、文字間隔を個別に設定でき、文字とロゴはまとめて拡大・縮小できます。
- JPEG または PNG で書き出せます。出力サイズは、元のサイズ（写真を元のピクセルで描画し、最長辺は 8000 px まで）またはカスタム（長辺を 256〜8000 px で入力）から選べ、元の写真を拡大することはありません。

ページ上部の横並びメニューで、3 つのツールを切り替えられます。各ツールの作業状態は保持されるため、別のツールに切り替えて戻っても、読み込んだ画像は失われません。

## インターフェースとテーマ

- 簡体字中国語、英語、日本語に対応し、右上で言語を切り替えられます。初回アクセス時は Nuxt i18n がブラウザーの言語を判定し、対応していない言語の場合は英語を使用します。
- 既定ではシステムの light / dark 設定に従います。ページ右上から手動でモードを順に切り替えることもできます。
- 配色は shadcn/ui の既定の neutral テーマに従い、意味に応じたカラートークンで light / dark モードに対応しています。
- 各モードには、文字、境界線、オーバーレイ、操作状態ごとの配色があります。写真の端を見分けやすくするため、画像プレビューの作業領域は常に暗い背景を使用します。
- すべてのスクロール領域で、細く角の丸い統一されたスクロールバーを使用しています。

## インストールとオフライン利用（PWA）

- インストールに対応するブラウザーでは、アドレスバーやブラウザーメニューのインストール項目から Film X をアプリとして追加できます。iOS Safari では「共有 → ホーム画面に追加」を使用してください。インストールとオフライン機能には HTTPS または localhost が必要です。
- 初回のオンラインアクセスでアプリのリソースのキャッシュが完了すると、3 つのツールすべてをオフラインで開き、表示言語も切り替えられます。画像のデコード、編集、書き出しは引き続きすべて端末内で行われます。
- 起動時、フォアグラウンドに戻ったとき、ネットワーク接続が復帰したとき、および実行中は 1 時間ごとに更新を確認します。新しいバージョンはバックグラウンドでダウンロードされ、すべての Film X ウィンドウに読み込み済み画像がなく、デコードや書き出しの処理もない状態になると、自動適用してページを再読み込みします。
- 画像や処理がある場合は更新待ちの状態を表示します。すべてのウィンドウの画像をクリアして処理の完了を待つか、Film X のウィンドウをすべて閉じると更新を適用できます。
- 画像はメモリにのみ保持され、再読み込みやページを閉じた後には復元できません。オフラインキャッシュには、読み込んだ画像や編集作業は保存されません。

## 技術スタック

アプリケーションフレームワークと UI：Nuxt 4 + Vue 3 + shadcn-vue + Reka UI + Tailwind CSS

多言語対応とテーマ：`@nuxtjs/i18n` + `@nuxtjs/color-mode`

画像処理と圧縮：UTIF + fflate

フレーム用フォント：`@fontsource`（OFL ライセンスのオープンソースフォント、ラテン文字サブセットのみ同梱）

インストール、オフライン対応、更新：`@vite-pwa/nuxt` + Workbox

コード検査とフォーマット：TypeScript + Oxlint + Oxfmt

## ローカル開発

Node.js のバージョン管理には [mise](https://mise.jdx.dev/) を使用しています。現在は Node.js 24 に設定されています。

```bash
mise install
mise exec -- pnpm install
mise exec -- pnpm dev
```

開発サーバーは既定で `http://localhost:3000` で起動します。

## 検査とビルド

```bash
mise exec -- pnpm check
mise exec -- pnpm test:pwa
mise exec -- pnpm build
```

`test:pwa` は Node 標準の回帰テストで、複数ウィンドウの待機中・処理中・無応答・終了、スコープ、再試行、同時メッセージにおける更新の有効化条件を検証します。

`check` は、フォーマット検査、Oxlint、Nuxt の型検査を順に実行します。静的サイトの生成やビルド結果のプレビューには、次のコマンドを使用できます。

```bash
mise exec -- pnpm generate
mise exec -- pnpm preview
```

開発モードでは Service Worker を登録しません。本番 PWA の検証には、`mise exec -- pnpm build` の後に `mise exec -- pnpm preview` を実行するか、`mise exec -- pnpm generate` で生成した `.output/public` を静的サーバーで配信してください。検証環境にも HTTPS または localhost が必要です。

## PWA のデプロイ

- ルートパスと、`NUXT_APP_BASE_URL` で設定したサブパスへの配置に対応しています。ビルドとデプロイでは同じベースパスを使用してください。
- `sw.js`、`pwa-update-guard.js`、`manifest.webmanifest`、HTML には `Cache-Control: no-cache` を設定し、ブラウザーが更新を速やかに再検証できるようにしてください。静的ホスティングでは、これらのレスポンスヘッダーを別途設定する必要があります。
- 新しい静的リソースと Service Worker は同じリリースで公開し、リソースを先に、worker を後に公開してください。ローリングデプロイ中は古い `_nuxt` のハッシュ付きリソースも保持し、旧バージョンを実行中のウィンドウから引き続き読み込めるようにしてください。

## コード構成

- `app/pages`：ハーフサイズ分割、レイアウト合成、フォトフレームのページ、および各ツールのワークフロー制御。
- `app/components/film`：読み込み、画像キュー、プレビュー、パラメーター調整、書き出しの共通コンポーネント。
- `app/composables`：ファイルキュー、自動検出、画像プレビュー、一括書き出しの状態管理。
- `app/types`：画像項目、分割設定、書き出し形式などの共通型。
- `app/utils`：画像のデコード、検出、切り抜き、回転、形式変換、EXIF の読み取り、フレーム描画のユーティリティ。
- `app/assets/css`：グローバルテーマ、色、基本的な UI 部品のスタイル、フレーム用フォントの読み込み。
- `app/assets/frame-logos`：フォトフレームで使うカメラブランドのロゴ SVG と、その出典の説明。
- `public`：favicon、PWA アイコン、更新保護スクリプト `pwa-update-guard.js` などの公開静的リソース。

ハーフサイズ分割のワークフローは、個人プロジェクト [Full2Half](https://github.com/haizakura/full2half) のソースコードを再利用し、Film X の共通ページ構成とテーマシステムに合わせて再構成しています。

## 画像処理について

- 画像処理はすべてブラウザー内で行われ、サーバーにアップロードされることはありません。
- フォトフレームが EXIF を読み取るときは、ファイル内のメタデータ部分だけを必要に応じて読み込み、そのために大きな TIFF 全体を読み込むことはありません。プレビューは縮小したコピーで描画し、書き出し時に選択したサイズで元の画像から描き直します。
- 自動分割では、中央領域の縦方向の明るさ、テクスチャ、境界の変化を解析します。中央の隙間を確実に検出できない場合は、ピクセルを削除しません。
- TIFF はブラウザー内でデコードされます。ハーフサイズ分割では JPEG、PNG、WebP、TIF で書き出せます。TIF は非圧縮の 8 ビット RGBA ピクセルを使用し、分割と 90° 単位の回転を行うことで、再度の非可逆エンコードを避けます。高ビット深度の TIFF 入力も、ブラウザー側で 8 ビット RGBA にデコードされる制約を受けます。
